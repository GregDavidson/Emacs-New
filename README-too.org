*** [[https://codeberg.org/ashton314/emacs-bedrock/issues/73][Please consider gating features in your init files so they can be upgraded with a pull #73]]

I love the curated minimum of emacs-bedrock!

I like most of what's in the Bedrock init files
- but not quite everything!

If I change those files
- then it's difficult to upgrade to a new emacs-bedrock version with a simple pull.

My suggestion to fix this
- rename extras/ to bedrock/
- move existing early-init.el and init.el to bedrock/
- add a check before each feature in all bedrock/*.el files which checks if that feature is NOT wanted
- create new early-init.el and init.el files which simply load the bedrock files, along with a comment about how to turn any unwanted features off.

This also has the nice side-effect that emacs customizations won't be added to the bedrock/init.el file.
- I will still: (setq custom-file (concat user-emacs-directory "custom.el"))
- but it's no longer important!

Maybe a few things should be gated by a check that the feature IS wanted
- e.g. loading of the extra files.

This could be done various ways.
- A bedrock-features association list of feature -> boolean pairs would work but might be overkill.
